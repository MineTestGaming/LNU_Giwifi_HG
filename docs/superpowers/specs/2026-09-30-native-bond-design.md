# Flutter 桌面原生网卡聚合

用户要求：优先使用系统原生绑定；仅纳入已认证网卡；Checkbox 选择成员。

保留单网卡认证出口，在旁边增加独立聚合卡片。每个候选 IPv4 的状态通过绑定该源地址的 AuthService.checkOnline 验证；未在线、过期、移除、地址变化、重复地址均不能加入。开始操作时再次逐卡验证，不能依赖保存的状态。

Windows 仅在 Windows Server 且 NetLbfo 可用时创建 SwitchIndependent / Dynamic Team；Windows 客户端显示不支持。macOS 用 networksetup 的 LACP，仅支持系统确认可绑定的以太网设备，需要交换机 LACP。Linux 用 NetworkManager balance-tlb，仅接受物理以太网。所有成员必须使用 DHCP，处于相同 IPv4 子网和网关，拒绝静态地址、Wi-Fi、VPN、已被其他聚合占用的设备。

系统操作需要界面确认以及系统管理员授权。只操作本次随机名称创建的聚合，记录恢复信息；Linux 创建独立临时连接配置，不改写原有连接。失败、聚合接口认证失效、停止聚合时删除自身聚合并恢复原连接。恢复失败时保留恢复记录并提供重试，重启应用能恢复未完成的操作。不得在测试或开发过程中修改本机真实网络。

原生绑定生成单个 IP/MAC，原认证不能直接继承。创建后等待 IPv4，并通过聚合接口再次确认在线，失败就回滚；运行期间每 60 秒验证聚合接口。原生模式只能证明创建前各成员认证和创建后逻辑接口认证，不能持续保留各物理成员独立校园网会话；界面说明这一限制。能力不满足时清楚报错，本次不引入本地代理或远端隧道。

验证：离线/未知/过期状态拒绝、操作前重新验证、创建后未知自动恢复、恢复失败保持记录、脚本参数转义、平台能力限制、Checkbox 交互与设置兼容、全部 Flutter 测试和静态分析。补齐 Linux runner；macOS 分发版退出 App Sandbox 以调用系统授权工具，保留 JIT 调试设置。
